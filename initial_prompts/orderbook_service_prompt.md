# Промпт: Реализация сервиса для работы со стаканом ордеров в Trading APIs & Exchange

## Контекст задачи
Необходимо реализовать сервис для работы со стаканом ордеров (OrderBook) как часть модуля Trading APIs & Exchange системы VANTA. Сервис должен обеспечивать унифицированный доступ к данным стакана ордеров через REST API и WebSocket API биржи Bybit, с поддержкой различных уровней глубины стакана и эффективной обработкой инкрементальных обновлений.

## Структура модулей

Основные компоненты должны быть созданы в следующих пакетах:

1. REST провайдер: `exchange_api/services/bybit/market_data_rest_service.py`
   - Класс `BybitMarketDataRestProvider` (уже существует, необходимо реализовать метод)

2. WebSocket провайдер: `exchange_api/services/bybit/market_data_stream_service.py` 
   - Класс `BybitMarketDataStreamProvider` (уже существует, необходимо реализовать метод)

3. Процессор обновлений: `exchange_api/services/bybit/orderbook_delta_processor.py`
   - Класс `OrderBookDeltaProcessor` (необходимо создать)

4. Интерфейсы (уже реализованы):
   - `exchange_api/interfaces/market_data.py`
   - Классы `IMarketDataRestProvider` и `IMarketDataStreamProvider`

## Требуемая функциональность

### 1. Реализация REST API для получения стакана ордеров

Требуется реализовать метод `get_orderbook` в классе `BybitMarketDataRestProvider`, который должен:
- Принимать символ инструмента и опциональную глубину стакана
- Вызывать соответствующий метод базового клиента Bybit
- Преобразовывать полученные данные в унифицированную модель `OrderBookData`
- Обрабатывать ошибки API и повторять запросы при необходимости

Метод должен соответствовать сигнатуре интерфейса `IMarketDataRestProvider.get_orderbook`.

### 2. Реализация WebSocket подписки на обновления стакана ордеров

Требуется реализовать метод `subscribe_to_orderbook` в классе `BybitMarketDataStreamProvider`, который должен:
- Формировать правильный WebSocket канал в формате `orderbook.{depth}.{symbol}`
- Устанавливать подписку на этот канал через `WebSocketManager`
- Преобразовывать полученные сообщения WebSocket в формат `OrderBookData`
- Поддерживать различные глубины стакана в соответствии с API Bybit
- Обрабатывать как полные снимки (snapshot), так и инкрементальные обновления (delta)

Метод должен соответствовать сигнатуре интерфейса `IMarketDataStreamProvider.subscribe_to_orderbook`.

### 3. Разработка обработчика инкрементальных обновлений

Требуется создать компонент `OrderBookDeltaProcessor` для:
- Обработки инкрементальных обновлений стакана
- Поддержания актуального состояния стакана на стороне клиента
- Определения типа обновления (снимок/дельта)
- Синхронизации состояния при потере сообщений

## Технические детали

### Модель данных OrderBookData
Уже имеется модель `OrderBookData` в пакете `models/market_data/orderbook.py`, которая включает:
- Списки уровней спроса (bids) и предложения (asks)
- Методы для сортировки и обработки уровней стакана
- Метод `apply_delta` для применения инкрементальных обновлений
- Методы для конвертации из различных форматов данных

### Bybit API для стакана ордеров
- REST API эндпоинт: `/v5/market/orderbook` (определен в `MarketDataEndpoints.ORDERBOOK`)
- WebSocket канал: `orderbook.{depth}.{symbol}` (определен в `PublicWebSocketChannels.ORDERBOOK`)
- Формат данных: списки [price, size] для bids и asks
- Особенности: разная глубина стакана, наличие как снимков, так и обновлений

### Поддерживаемые глубины стакана
Bybit поддерживает следующие значения глубины (limit):
- 1, 25, 100, 200, 500 для спотовых рынков
- 1, 25, 50 для деривативов

## Взаимодействие компонентов

1. `BybitMarketDataService` вызывает методы REST и WebSocket провайдеров
2. REST и WebSocket провайдеры получают данные от API биржи
3. Для WebSocket подписок используется `OrderBookDeltaProcessor` для обработки обновлений
4. Получатель данных (пользователь API) получает уже нормализованные данные в формате `OrderBookData`

## Критерии приемки

1. Поддержка различных глубин стакана ордеров
2. Корректная обработка и применение инкрементальных обновлений
3. Высокая производительность при большом количестве обновлений
4. Отсутствие хранения данных на стороне сервиса, только проксирование

## Примечания по реализации

1. **Валидация параметров**: проверять поддерживаемые значения глубины стакана для разных типов рынков
2. **Обработка ошибок**: реализовать механизмы восстановления при сбоях API
3. **Производительность**: оптимизировать структуры данных и алгоритмы обработки для минимизации задержек
4. **Синхронизация**: корректно обрабатывать ситуации потери сообщений или рассинхронизации стакана

Для реализации этой задачи потребуется работа с базовыми компонентами и моделями данных, которые уже частично реализованы в проекте.
