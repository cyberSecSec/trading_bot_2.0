## **Торговая стратегия**

<aside>
🧠

**Идея**
Рынок не хаотичен. Он действует волнами и фазами, а алгоритмы (включая манипуляции) подстраиваются под контекст.Наша стратегия **не пытается ловить все сигналы**, а **распознаёт, что сейчас делает рынок**, и **включает нужные фильтры**.

</aside>

**🔁 Как работает стратегия:**

1. **Определяется контекст рынка** (режим):
    - 📈 Импульсный (волатильность, пробои)
    - 🔄 Боковик (флэт, ложные пробои)
    - 🧊 Иллюзия глубины (стаканная манипуляция)
    - 📉 Пост-новость (перезагрузка ликвидности)
    - 🪤 Ловушечный режим (всё выглядит красиво, но вынос)
2. **Подключаются только те манипуляции, которые характерны для этого режима.** Например:
    - В импульсном рынке — ловим Momentum Fake, Spoof, Trap Fade
    - В ловушечном — фильтруем Pattern Reversal, Double Bait, Volume Injection
    - В боковике — включается защита от Range Trap, Candle Trickery, False Accumulation
3. **Бот действует в зависимости от того, какая манипуляция активна:**
    - ❌ Не входит в ловушку
    - ⏳ Ждёт подтверждение движения
    - 🧲 Разрешает вход в контр-движение, если ловушка подтверждена
    - 🛡️ Включает защитный режим, если манипуляций слишком много подряд
4. **Все действия логируются и можно проверить, почему бот принял то или иное решение.**

## **Этап 3: Контроллер определения контекста рынка (режима)**

 **I. Цель контроллера**

Контекстный контроллер отслеживает **ключевые рыночные метрики** (дельта, OI, объём, волатильность, ликвидации) и **динамически определяет активный режим**:

| **Режим рынка** | **Признаки** |
| --- | --- |
| momentum | Всплеск объёма + сильное движение + follow-up свечи |
| trap_mode | OI растёт, цена не двигается, есть ликвидации, свечи в обратку |
| layering_mode | Частые ложные пробои + narrow range + объём без направления |
| news_volatility | Импульс за 10 мин до события, разворот на новости, спайки ликвидаций |
| hft_noise | Много отмен заявок, delta noise, короткие свечи без импульса |
| flat_low_vol | Диапазон < 0.5%, объёмы стабильны, свечи плоские |

 **II. Логика: как определить режим**

```python
def detect_market_context(klines, oi_data, delta_list, liq_data, orderbook_noise):

    context_flags = {
        "momentum": False,
        "trap_mode": False,
        "layering_mode": False,
        "news_volatility": False,
        "hft_noise": False,
        "flat_low_vol": False
    }

    ## Расчёты:
    closes = [float(k[4]) for k in klines[-6:]]
    volumes = [float(k[5]) for k in klines[-6:]]
    highs = [float(k[2]) for k in klines[-6:]]
    lows = [float(k[3]) for k in klines[-6:]]

    range_ = max(highs) - min(lows)
    price_change = abs(closes[-1] - closes[0]) / closes[0] * 100
    avg_volume = sum(volumes) / len(volumes)
    vol_now = volumes[-1]
    delta_now = delta_list[-1] if delta_list else 0
    delta_mean = sum(delta_list[-5:]) / 5 if delta_list else 0
    liq_now = liq_data[-1] if liq_data else 0

    oi_now = float(oi_data[-1]['openInterest'])
    oi_prev = float(oi_data[-2]['openInterest'])
    delta_oi = oi_now - oi_prev

    # ➤ Momentum Mode
    if vol_now > avg_volume * 2 and price_change > 0.6 and delta_now > delta_mean:
        context_flags["momentum"] = True

    # ➤ Trap Mode
    if delta_oi > 500 and price_change < 0.2 and liq_now > 1_000_000:
        context_flags["trap_mode"] = True

    # ➤ Layering Mode
    if range_ < closes[-1] * 0.004 and avg_volume < 500000 and delta_now * delta_mean < 0:
        context_flags["layering_mode"] = True

    # ➤ News Volatility Mode
    if liq_now > 1_500_000 and price_change > 1.0:
        context_flags["news_volatility"] = True

    # ➤ HFT Noise
    if orderbook_noise >= 5 and range_ < closes[-1] * 0.002:
        context_flags["hft_noise"] = True

    # ➤ Flat / Low Vol
    if range_ / closes[-1] < 0.005 and avg_volume < 400000 and abs(delta_now) < 1000:
        context_flags["flat_low_vol"] = True

    return context_flags
```

def activate_filters(context):
    if context == "momentum":
        return [
            "MomentumFake", "VolumeInjectionTrap", "LiquidationTrap",

def bot_reaction(signal, active_filters):
    if signal in active_filters:
        if "Trap" in signal or "Fake" in signal:
            return {
                "action": "block_entry",
                "duration": 3,
                "note": f"⚠️ Entry blocked due to {signal}"
            }
        elif "Layer" in signal or "Wall" in signal:
            return {
                "action": "observe_only",
                "note": f"👀 Observing due to {signal}"
            }
        else:
            return {
                "action": "defer_decision",
                "note": f"📉 Signal delayed for {signal}"
            }
    else:
        return {
            "action": "proceed",
            "note": "✅ Signal allowed"

**4. Сборка стратегии**

```python
def trading_strategy_engine(signal_detected, market_data):
    context = detect_market_context(
        volume_spike=market_data["volume_spike"],
        delta=market_data["delta"],
        oi_change=market_data["oi_change"],
        range_pct=market_data["range_pct"],
        walls_present=market_data["walls_present"]
    )

    filters = activate_filters(context)

    bot_action = bot_reaction(signal_detected, filters)

    return {
        "context": context,
        "filters": filters,
        "decision": bot_action
    }
```

На данном этапе мы сосредоточимся на финальной интеграции разработанной стратегии, проведении тестирования и создании сценарного симулятора для оценки её эффективности.

- **Логика поведения бота**: определяет действия в ответ на выявленные манипуляции.

Интеграция осуществляется посредством модульного подхода, где каждый компонент взаимодействует через чётко определённые интерфейсы, обеспечивая гибкость и масштабируемость системы.

1. **Тестирование стратегии:**

Проводим комплексное тестирование, включающее:

- **Модульное тестирование**: проверка отдельных компонентов стратегии на корректность работы.
- **Интеграционное тестирование**: оценка взаимодействия между компонентами и их совместной работы.
- **Системное тестирование**: проверка всей системы в целом на соответствие требованиям и ожидаемому поведению.

Для автоматизации тестирования используем фреймворк pytest, который позволяет эффективно создавать и управлять тестами в Python.

## **Несколько манипуляций могут работать одновременно. Но:**

### **Разбор по уровням:**

1. **Одна активная “доминирующая” манипуляция + вторичные слои**

- Обычно **1 манипуляция — основная фаза**, она определяет контекст (например, *Liquidation Trap* или *False Accumulation*).
- Остальные могут быть **вспомогательными/перекрывающимися**, например:
    - *Candle Trickery* внутри *Volume Injection Trap*
    - *OI Trap* в рамках *Wave Fakeout*
    - *Double Bait Trap* — как накладка на любую из визуальных ловушек.

2. **Манипуляции одной природы могут накладываться**

- Пример:
    - *Classic Pattern Trap* + *Pre-News Trap* → толпа строит паттерн, а новость “ломает” его в нужную сторону.
    - *Layering* + *Spoofing* — часто идут в паре как одна сессия давления через стакан.

### Что это значит для стратегии:

**Контроллер контекста** должен:

- Определять **доминирующую манипуляцию** (по структуре, метрикам).
- Выявлять **совпадение с другими сигналами** — усиливает вес.
- Не допускать конфликта фильтров (например, вход по *Momentum*, когда активна *OI Trap*).

### Практический принцип:

> **“Манипуляции — это не сигналы, это поведение.”**
> 

Они могут сливаться, усиливать или маскировать друг друга.

Бот должен **реагировать не на название ловушки, а на комбинацию условий.**

## Группы рыночного контекста

<aside>
☝🏽

**Распределение манипуляций по типу рыночного контекста в боте —** это базис адаптивной реакции алгоритма на изменяющуюся среду. Это позволяет боту не просто искать сигналы, а понимать, в каком контексте эти сигналы работают / не работают, и корректировать своё поведение в режиме реального времени.

**Тип рыночного шума** — это основа фильтрации сигнала и управления риском.

Бот перестаёт быть "ракетой на сигнале" — он становится **"контекстно-адаптивным трейдером"**, способным отличить ловушку от возможности.

### **1. Ликвидностный шум (Liquidity Traps)**

Манипуляции, направленные на вынос стопов, сбор ликвидности, запуск каскадов ликвидаций.

**Манипуляции:**

1. Fake Breakout / Ложные пробои
2. Stop Hunt + Shakeout / Сброс ликвидности перед движением
3. Stair-Step Hunt / Стоповые ступеньки
4. Liquidation Trap / Вброс ликвидаций для поджига движения
5. Open Interest Trap / Работа против открытого интереса

**Реакция бота:**

- Исключение входов по прямым пробоям уровня без подтверждения
- Вход **на возврате (retest)** или по факту закрепления
- Переход на **лимитные заявки вместо рыночных**
- Учет **кластера стопов / ликвидаций** как предупреждение, не как триггер
- Уменьшение размера позиции в моменты высоких всплесков OI

### **2. Структурный шум (Pattern Distortion)**

Ловушки на базе "учебных" структур, классических фигур, паттернов.

**Манипуляции:**

1. Pattern Baiting / Выманивание ликвидности через паттерны
2. Pattern Reversal Trap / Инверсия классического паттерна
3. Momentum Fake / Псевдо-импульс
4. False Accumulation / Псевдо-накопление
5. Wave Fakeout Logic / Контр-волновое поведение
6. Classic Pattern Trap / Забор ликвидности на "классике"

**Реакция бота:**

- Фильтрация **всех паттерн-сигналов по подтверждению дельтой и объёмом**
- Игнор входов **по пробою без закрепления свечи**
- Использование **анти-паттерн логики** — вход в противоположную сторону после ложного пробоя
- Работа **на возврате цены внутрь фигуры**

### **3. Объёмностаканный шум (Orderbook Illusions)**

Манипуляции через стакан, объёмы, ленту — симулируют интерес, которого нет.

**Манипуляции:**

1. Spoofing / Вброс объема в стакан
2. Layering / Ковровое давление
3. Volume Injection / Подмена объёма
4. Data Injection Trap / Перерисовка дельты и объёма
5. Order Flow Splitting / Разделение ленты

**Реакция бота:**

- Игнор объёмных сигналов без подтверждения исполнения (no real fill)
- Отключение **реакций на стакан** при высокой отмене ордеров
- Анализ: "Есть ли объём, но нет цены?" → вероятен фейк
- Использование фильтров по **execution ratio и lifetime ордера**

### **4. Контекстный шум (Event Disruption)**

Манипуляции, связанные с новостями, временем суток, экономическими ожиданиями.

**Манипуляции:**

1. Pre-News Trap / Манипуляции перед новостями
2. Intentional Range Traps / Алгоритмический флэт
3. Candle Trickery / Подмена поведения свечей
4. Candle Context Mismatch / Контекстный обман свечей

**Реакция бота:**

- Фильтрация входов за **15 минут до и после** новостей
- Игнор свечных сигналов без объёмного подтверждения
- Проверка: свеча ≠ контекст? → отказ от входа
- Ориентация на post-news откатные зоны, не на первые импульсы

### **5. Антибот шум (AI-Adaptive Baiting)**

Манипуляции против ИИ, обучающихся стратегий и предсказуемых паттернов.

**Манипуляции:**

1. Meta-AI Countering / Слежка за поведением ИИ
2. Double Bait Trap / Механика двойного сигнала

**Реакция бота:**

- Использование мета-логики: "Если это второй сигнал подряд — вероятна ловушка"
- Временная задержка подтверждения входа на 1–2 свечи
- Повышенный вес **вторичных метрик (OI, дельта, объем исполнения)**
- Оценка **противоположного сценария** как основной альтернативы
