# Layering

1. **"Ковровое давление" (Layering)**
- Ставятся много **мелких ордеров на продажу/покупку** вблизи текущей цены
- Иллюзия «стены» спроса или предложения
- Цена отскакивает/тормозит — **даёт фальшивую зону поддержки/сопротивления**

**Манипуляция №4: "Ковровое давление" (Layering)**

### **1. Идентификация манипуляции: как работает и что искать**

**Что это**:

Layering — HFT-манипуляция, при которой в стакан выставляются десятки мелких лимитных ордеров по одной стороне (bid или ask) на ограниченной глубине (1–5 тиков от текущей цены). Это создаёт иллюзию значительного интереса, заставляя участников рынка поверить в наличие сильной поддержки или сопротивления.

**Цель**:

- Имитировать стену спроса/предложения
- Замедлить движение цены или развернуть его
- Ввести в заблуждение маркетмейкеров и ботов
- Поддерживать зону “фиктивной” ликвидности

**Варианты поведения**:

1. **Статичный Layering** — давление стоит на месте, не двигается
2. **Динамический Layering (Layer Follow)** — заявки "шагают" вслед за движением цены

**Как проявляется**:

- Плотная группа из ≥5 ордеров на каждом из 3–5 ближайших тиков
- Суммарный объём на этих уровнях значительно выше среднего
- Размер заявок небольшой, но общее визуальное давление создаётся
- Заявки сохраняются 30+ секунд или "шагают" за ценой
- Сделки на этих уровнях практически не проходят
- При приближении цены — заявки исчезают частично, цена отскакивает

### **2. Методы идентификации и метрики**

| **Признак** | **Что отслеживать** | **Где брать** |
| --- | --- | --- |
| Группировка мелких ордеров на 2–5 тиках от цены | ≥5 ордеров на каждом уровне, равномерно распределены | WebSocket /v5/public/orderbook.25 |
| Суммарный объём и count-density | Общий объём и количество ордеров на стороне давления | WebSocket стакан |
| Bid/Ask imbalance | Дисбаланс между сторонами стакана (например, > 60%) | WebSocket стакан |
| Layer Follow | Движение слоя вслед за ценой (смещение давления на 1 тик вверх/вниз) | Сравнение исторических snapshot'ов |
| Время удержания слоя | ≥30 секунд на одних и тех же уровнях | История стакана по времени |
| Реакция цены и отсутствие сделок | Цена реагирует (отскок/замедление), но объём не исполняется | /v5/market/recent-trade |
| Execution rate | Доля реально исполненных ордеров от общей массы на давящем уровне | расчёт по ленте |

### **3. Формулы и логика обработки**

1. **Обнаружение коврового давления**

Плотность объёма на глубине:

```python
density = sum(size[0:5]) / 5
order_count_density = len([1 for s in size[0:5] if s > 0]) / 5
```

Условия фильтрации:

- Все заявки ≤ 10% от суммарного объёма на уровне (отсеиваем spoof)
- density > средний по рынку × 2
- order_count_density ≥ 5
1. **Дисбаланс между сторонами**

```python
imbalance = (sum(bid_volume[1:5]) - sum(ask_volume[1:5])) / (sum(bid_volume[1:5]) + sum(ask_volume[1:5]))
```

Layering фиксируется при |imbalance| > 0.6

1. **Layer Follow — шаг за ценой**

```python
if abs(last_layer_price - current_layer_price) == tick_size:
    layer_follow = True
```

1. **Поддержание давления**
- Сохраняем snapshot стакана каждые 5 секунд
- Если объем/количество ордеров сохраняется ≥ 30 секунд
- Execution rate < 10% (реальных сделок по этим уровням почти нет)
1. **Реакция цены**
- Цена ≥3 раза отскакивает от зоны давления
- После исчезновения давления — пробой с ускорением

### **4. Логгер (Python + WebSocket)**

```python
from pybit.unified_trading import WebSocket
import time

layering_threshold = 0.6
watch_ticks = 5
symbol = "BTCUSDT"
layering_flags = []

def detect_layering(orderbook_data):
    bids = orderbook_data['b']
    asks = orderbook_data['a']

    bid_sizes = [float(b[1]) for b in bids[:watch_ticks]]
    ask_sizes = [float(a[1]) for a in asks[:watch_ticks]]

    bid_count = len([s for s in bid_sizes if s > 0])
    ask_count = len([s for s in ask_sizes if s > 0])

    bid_sum = sum(bid_sizes)
    ask_sum = sum(ask_sizes)

    if bid_sum + ask_sum == 0:
        return

    imbalance = abs(bid_sum - ask_sum) / (bid_sum + ask_sum)

    if imbalance > layering_threshold and bid_count >= 5:
        timestamp = int(time.time())
        layering_flags.append({
            "timestamp": timestamp,
            "side": "bid" if bid_sum > ask_sum else "ask",
            "imbalance": imbalance,
            "order_count": bid_count if bid_sum > ask_sum else ask_count
        })
        print(f"[{timestamp}] Layering detected on {'bid' if bid_sum > ask_sum else 'ask'} side | Imbalance: {round(imbalance, 2)} | Orders: {bid_count if bid_sum > ask_sum else ask_count}")

ws = WebSocket(
    testnet=False,
    channel="orderbook.25",
    symbol=symbol,
    callback=detect_layering
)

while True:
    time.sleep(1)

```

**Резюме — ключевые условия для Layering**

1. В стакане на 1–5 тиках наблюдается группировка ≥ 5 мелких ордеров на каждом уровне.
2. Суммарный объём значительно выше средней плотности, но ордера не исполняются.
3. Плотность сохраняется ≥ 30 секунд.
4. Дисбаланс по одной стороне стакана > 60%.
5. Execution rate (реальных сделок) по уровню < 10%.
6. Если слой "шагает" за ценой и остаётся неисполненным, — это динамическое давление.
7. После исчезновения давления — возможен быстрый пробой зоны.
