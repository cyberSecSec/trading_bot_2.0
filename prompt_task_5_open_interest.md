# Реализация сервиса для данных об открытом интересе (Open Interest)

## Контекст задачи

В рамках модуля Trading APIs & Exchange необходимо разработать сервис для получения данных об открытом интересе (Open Interest) через REST API и подписку на обновления через WebSocket API биржи Bybit. Данный сервис должен предоставлять унифицированный доступ к данным об открытом интересе (текущим и историческим) и обеспечивать их нормализацию в стандартный формат для использования другими модулями системы.

## Открытый интерес и его значение

Открытый интерес (Open Interest) - это общее количество открытых фьючерсных/опционных контрактов, которые еще не были закрыты или исполнены. Этот показатель является важным индикатором рыночной активности и может использоваться для:
- Выявления манипуляций (Open Interest Trap)
- Расчета изменений OI относительно цены
- Определения фаз накопления/распределения
- Анализа расхождений между OI и ценой

## API эндпоинты Bybit для Open Interest

### REST API
- Основной эндпоинт: `/v5/market/open-interest`
- Формат данных: объекты с временной меткой и значением открытого интереса
- Особенности: значения могут быть представлены в разных единицах (контракты, USD)

### WebSocket API
- Канал: `openInterest.{symbol}`
- Формат: потоковые обновления значений открытого интереса

## Задача

Необходимо реализовать сервис для получения и обработки данных об открытом интересе, который будет интегрироваться с существующими компонентами системы.

### Подзадачи

1. **REST API компоненты**:
   - Добавить в класс `BybitMarketDataRestProvider` методы:
     - `get_open_interest(symbol)` - получение текущего открытого интереса
     - `get_open_interest_history(symbol, period, limit)` - получение исторических данных об открытом интересе
   - Реализовать обработку ошибок и ограничений API для запросов открытого интереса
   - Обеспечить нормализацию данных в формат модели `OpenInterestData`

2. **WebSocket компоненты**:
   - Добавить в класс `BybitMarketDataStreamProvider` метод:
     - `subscribe_to_open_interest(symbol, callback)` - подписка на обновления открытого интереса
   - Реализовать обработку сообщений об открытом интересе
   - Обеспечить нормализацию данных в унифицированный формат

3. **Дополнительные компоненты**:
   - Разработать механизм сравнения данных из REST и WebSocket для выявления расхождений
   - Создать систему обнаружения аномальных изменений открытого интереса
   - Реализовать обработку специфических форматов данных Bybit

## Требования к реализации

1. **Общие требования**:
   - Сервис должен быть полностью асинхронным (использовать asyncio)
   - Код должен соответствовать общему стилю и структуре проекта
   - Необходимо использовать уже существующие компоненты соединения (ConnectionManager, WebSocketManager)
   - Сервис не должен хранить исторические данные, а только предоставлять доступ к ним

2. **Обработка данных**:
   - Все данные должны быть нормализованы в формат модели `OpenInterestData`
   - Необходимо обеспечить валидацию входных и выходных данных
   - Необходимо корректно обрабатывать временные метки и значения в разных единицах измерения

3. **Обработка ошибок**:
   - Реализовать обработку всех возможных ошибок API Bybit
   - Обеспечить механизм повторных попыток при временных сбоях
   - Логировать все ошибки с достаточным контекстом для диагностики

4. **Производительность**:
   - Минимизировать задержки при получении и обработке данных
   - Оптимизировать использование ресурсов (CPU, память)
   - Обеспечить эффективную работу с WebSocket для минимизации задержек

## Структура модели данных

Модель `OpenInterestData` должна содержать следующие поля:
- `symbol: str` - торговый символ (например, "BTCUSDT")
- `timestamp: int` - временная метка в миллисекундах
- `open_interest: Decimal` - значение открытого интереса
- `open_interest_value: Decimal` - стоимость открытого интереса в USD (если доступно)
- `unit: str` - единица измерения (контракты, монеты и т.д.)

## Примеры использования

### Пример получения текущего открытого интереса

```python
async def example_get_open_interest():
    # Инициализация провайдера
    rest_provider = BybitMarketDataRestProvider(config)
    
    # Получение текущего открытого интереса для BTCUSDT
    oi_data = await rest_provider.get_open_interest("BTCUSDT")
    
    # Использование данных
    print(f"Открытый интерес для BTCUSDT: {oi_data.open_interest} {oi_data.unit}")
    print(f"Стоимость в USD: {oi_data.open_interest_value} USD")
    print(f"Временная метка: {oi_data.timestamp}")
```

### Пример получения истории открытого интереса

```python
async def example_get_open_interest_history():
    # Инициализация провайдера
    rest_provider = BybitMarketDataRestProvider(config)
    
    # Получение истории открытого интереса для BTCUSDT
    # period: 5min, 15min, 30min, 1h, 4h, 1d
    # limit: максимальное количество записей (по умолчанию 50, максимум 200)
    oi_history = await rest_provider.get_open_interest_history("BTCUSDT", period="1h", limit=100)
    
    # Использование данных
    for oi_data in oi_history:
        print(f"[{oi_data.timestamp}] OI: {oi_data.open_interest} {oi_data.unit}")
```

### Пример подписки на обновления открытого интереса

```python
async def example_subscribe_to_open_interest():
    # Инициализация провайдера
    stream_provider = BybitMarketDataStreamProvider(config)
    
    # Колбэк-функция для обработки обновлений
    async def on_open_interest_update(oi_data: OpenInterestData):
        print(f"Обновление OI для {oi_data.symbol}: {oi_data.open_interest} {oi_data.unit}")
    
    # Подписка на обновления открытого интереса для BTCUSDT
    await stream_provider.subscribe_to_open_interest("BTCUSDT", on_open_interest_update)
    
    # Ожидание обновлений
    try:
        while True:
            await asyncio.sleep(1)
    except KeyboardInterrupt:
        # Отписка при завершении
        await stream_provider.unsubscribe_from_open_interest("BTCUSDT")
```
