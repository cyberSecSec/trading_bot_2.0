# Задача: Определение базовых интерфейсов для модуля Trading APIs & Exchange

## Контекст
Мы реализовали модели данных для Trading APIs & Exchange, которые представляют данные рынка и торговые операции в унифицированном формате. Теперь нам необходимо определить интерфейсы, через которые другие компоненты системы VANTA будут взаимодействовать с модулем Trading APIs & Exchange.

Интерфейсы должны абстрагировать специфику работы с различными биржами и предоставлять унифицированные методы для:
- Получения рыночных данных через REST API
- Подписки на потоковые рыночные данные через WebSocket
- Выполнения торговых операций через REST API
- Получения обновлений о торговых операциях через WebSocket

## Задача
Разработать набор абстрактных интерфейсов (абстрактные классы), которые будут использоваться для взаимодействия с модулем Trading APIs & Exchange. Интерфейсы должны быть независимы от конкретной биржи и предоставлять методы, соответствующие потребностям других компонентов.

### Часть 1: Интерфейсы для рыночных данных
Необходимо создать:
1. **IMarketDataRestProvider** - интерфейс для получения рыночных данных через REST API
2. **IMarketDataStreamProvider** - интерфейс для подписки на потоковые рыночные данные через WebSocket
3. **IMarketDataProvider** - объединяющий интерфейс, включающий методы обоих вышеуказанных интерфейсов

### Часть 2: Интерфейсы для торговых операций
Необходимо создать:
1. **ITradeRestExecutor** - интерфейс для выполнения торговых операций через REST API
2. **ITradeStreamExecutor** - интерфейс для подписки на обновления о торговых операциях через WebSocket
3. **ITradeExecutor** - объединяющий интерфейс, включающий методы обоих вышеуказанных интерфейсов

## Требования
1. Все интерфейсы должны быть определены как абстрактные базовые классы (ABC) с типизацией параметров и возвращаемых значений
2. Методы должны использовать асинхронный подход (asyncio)
3. Интерфейсы должны быть независимы от конкретной биржи
4. Все методы должны иметь документацию с описанием параметров, возвращаемых значений и возможных исключений

## Структура файлов
1. `exchange_api/interfaces/market_data.py` - интерфейсы для рыночных данных
2. `exchange_api/interfaces/trade_executor.py` - интерфейсы для торговых операций
3. `exchange_api/interfaces/__init__.py` - экспорт интерфейсов

## Детализация интерфейсов

### IMarketDataRestProvider
Методы для получения рыночных данных через REST API:
- `get_klines(symbol, interval, limit, start_time, end_time)` - получение OHLCV данных
- `get_orderbook(symbol, depth)` - получение стакана ордеров
- `get_recent_trades(symbol, limit)` - получение недавних сделок
- `get_open_interest(symbol)` - получение открытого интереса

### IMarketDataStreamProvider
Методы для подписки на потоковые рыночные данные через WebSocket:
- `subscribe_to_klines(symbol, interval, callback)` - подписка на OHLCV данные
- `subscribe_to_orderbook(symbol, depth, callback)` - подписка на стакан ордеров
- `subscribe_to_trades(symbol, callback)` - подписка на сделки
- `subscribe_to_liquidations(symbol, callback)` - подписка на ликвидации
- `subscribe_to_open_interest(symbol, callback)` - подписка на открытый интерес
- Методы для отписки от соответствующих каналов

### ITradeRestExecutor
Методы для выполнения торговых операций через REST API:
- `create_order(order_params)` - создание ордера
- `cancel_order(symbol, order_id)` - отмена ордера
- `cancel_all_orders(symbol)` - отмена всех ордеров
- `get_order(symbol, order_id)` - получение информации об ордере
- `get_active_orders(symbol)` - получение списка активных ордеров
- `get_position(symbol)` - получение информации о позиции
- `get_all_positions()` - получение списка всех позиций
- Методы управления параметрами торговли (кредитное плечо, режим маржи и т.д.)

### ITradeStreamExecutor
Методы для подписки на обновления о торговых операциях через WebSocket:
- `subscribe_to_order_updates(callback)` - подписка на обновления ордеров
- `subscribe_to_execution_updates(callback)` - подписка на исполнение ордеров
- `subscribe_to_position_updates(callback)` - подписка на изменения позиций
- `subscribe_to_balance_updates(callback)` - подписка на изменения баланса
- Методы для отписки от соответствующих каналов

## Ожидаемый результат
Полный набор интерфейсов, готовых для использования при разработке конкретных реализаций для различных бирж. Интерфейсы должны быть хорошо документированы, предоставлять четкие контракты, и быть независимыми от деталей реализации.
