# Задача разработки: Реализация адаптеров соединения для модуля Trading APIs & Exchange

## Контекст

Trading APIs & Exchange - это ключевой компонент системы VANTA, обеспечивающий унифицированный доступ к API криптовалютных бирж. Модуль является "тонким" клиентом, абстрагирующим специфику различных биржевых API и предоставляющим единый интерфейс для работы с рыночными данными и торговыми операциями.

На данный момент уже реализованы:
1. Базовая структура проекта с директориями и файлами-заглушками
2. Система конфигурации для работы с Bybit API (core/config.py)
3. Система логирования (utils/logger.py)
4. Иерархия исключений (exceptions.py)

## Задача

Необходимо разработать адаптеры соединения с использованием готовых библиотек для обеспечения надежного взаимодействия с API криптобирж.

### Цель задачи

Создать адаптеры и обёртки над существующими библиотеками для управления HTTP и WebSocket соединениями с биржей, обеспечивающие единый интерфейс взаимодействия и дополнительную специфичную для биржи функциональность.

### Подзадачи

1. Выбрать и интегрировать библиотеки для HTTP запросов (aiohttp/httpx) и WebSocket соединений (websockets/aiohttp.ws)
2. Разработать ConnectionManager как адаптер над HTTP-клиентом (connection/connection_manager.py)
3. Создать WebSocketManager как адаптер над WebSocket-клиентом (connection/websocket_manager.py)
4. Реализовать механизм переподключения с использованием библиотеки backoff (connection/reconnection_handler.py)

### Ожидаемый результат

1. ConnectionManager с функциональностью:
   - Адаптер над aiohttp для HTTP методов (GET, POST, PUT, DELETE)
   - Управление сессиями и таймаутами через конфигурацию
   - Единый интерфейс обработки ошибок и повторных попыток
   - Логика контроля частоты запросов (rate limiting)
   - Добавление заголовков аутентификации для Bybit API

2. WebSocketManager с функциональностью:
   - Адаптер над выбранной WebSocket библиотекой
   - Система подписок на каналы с учетом специфики Bybit
   - Унифицированная обработка входящих сообщений
   - Абстракция для авто-переподключения при обрывах

3. ReconnectionHandler с функциональностью:
   - Использование библиотеки backoff для экспоненциальной задержки
   - Логика переподключения и восстановления состояния
   - Расширенное логирование процесса переподключения

### Технические требования

1. Все компоненты должны быть асинхронными (asyncio)
2. Адаптеры должны обеспечивать полную функциональность для работы с API Bybit
3. Интеграция с библиотеками должна выполняться с соблюдением лучших практик
4. Компоненты должны быть устойчивы к сбоям сети и ошибкам API
5. Ресурсы должны корректно освобождаться при завершении работы
6. Необходимо обеспечить мягкую зависимость от конкретных библиотек для возможности их замены в будущем
7. Код должен быть хорошо документирован и покрыт типизацией

### Рекомендации по реализации

1. Использовать aiohttp как основную HTTP библиотеку из-за её производительности и широкого применения
2. Предусмотреть механизмы автоматической проверки состояния соединения (health check)
3. Реализовать логирование всех запросов и ответов для отладки
4. Обеспечить автоматический контроль за соблюдением rate limits биржи
5. Реализовать систему обратных вызовов (callbacks) для обработки событий WebSocket
6. Предусмотреть механизмы разделения подписок по разным соединениям для балансировки нагрузки

## Важно учесть при разработке

1. Все компоненты должны использовать один и тот же формат обработки ошибок и логирования
2. Необходимо учитывать особенности API Bybit, включая ограничения на частоту запросов
3. Компоненты соединения должны быть абстрактными и не зависеть от конкретной биржи
4. Специфичная для биржи функциональность должна быть реализована через механизмы расширения/наследования
5. Все публичные методы должны быть хорошо задокументированы

Пожалуйста, разработайте эти компоненты с соблюдением всех указанных требований и лучших практик асинхронного программирования в Python.
